The module is a flat collection of one file per supported language plus an index aggregator. `en.ts` declares the canonical `CatalogKey` type via `keyof typeof en` and exports the full English dictionary as the single source of truth; every other locale file (`bal.ts`, `hno.ts`, `pa.ts`, `ps.ts`, `sd.ts`, `skr.ts`, `ur.ts`) exports a `Partial<Record<CatalogKey, string>>` with translated values. `index.ts` re-exports each locale, builds a `CATALOG: Readonly<Record<Locale, Partial<Record<CatalogKey, string>>>>` map keyed by the `Locale` union from `lib/i18n/config`, derives `CATALOG_KEYS` from the English keys, and exposes `ENGLISH_TABLE` (English entries with empty/blank values stripped) as the fallback source. The comment in `index.ts` documents the deployment contract: this catalog is the authoring source of truth and is synced into the Supabase `translations` table by `scripts/sync-translations.mts`, so the app reads translations from the database at runtime rather than bundling them — enabling founder edits without redeploy. A Vitest test suite (`catalog.test.ts`) enforces three invariants: every English key has a non-empty trimmed value, no locale contains stray keys outside the English set, and all non-English translations are non-empty and free of `TODO` placeholders.
