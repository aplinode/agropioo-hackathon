Three parallel top-level folders form the documentation layer of the repo:
- `docs/` holds high-level project documentation (brand identity, information architecture, landing-page design/rationale, tech stack, feature list) plus the team-wide Spec-Driven Development guide (`spec-drvien-dev.md`) that defines the constitution → Research → Specify → Clarify → Build loop.
- `specs/<feature>/` is the canonical artifact store for each feature. Every feature folder follows a consistent shape: a `spec.md` describing Goal, User Scenarios, Functional Requirements (FR1..FRn), Edge Cases & Rules, Out of Scope, Acceptance Criteria, and often a Reconciliation section; a `research.md` capturing findings before writing the spec; and a `plan.md` or `plan.md`+`spec.md` pairing for backend-heavy features (e.g., `authentication/`). Cross-feature references are made by path (e.g., `specs/authentication/spec.md` reconciles against `specs/otp-verification/spec.md` and `specs/forgot-password/spec.md`).
- `adrs/` stores numbered Architectural Decision Records (e.g., `0003-auth-pass-architecture.md`) that record Context, Decision, and Consequences for cross-cutting choices and explicitly tie back to the originating spec's plan items (K1–K7).
Dependency direction is one-way: specs reference existing code paths and other specs but never vice versa; ADRs reference specs/plans as their source of truth. There is no build tooling — this module is purely authored Markdown consumed by developers and AI agents during the SDD loop.
