The app is split into three co-located concerns under one Next.js project: `(site)/[locale]/...` renders the public marketing pages with i18n routing; `(farmer)/...` wraps the authenticated farmer dashboard in its own route group with per-feature sub-routes (dashboard, farms, records, advisor, detect, prices, weather, notifications); `api/auth/*` exposes REST handlers for login, signup, OTP verify/resend, forgot/reset password flows, plus `api/health`. Both route groups consume shared React components from `components/` (marketing sections, auth shell, OTP stepper, app sidebar/bottom tabs) so UI is reused across the marketing and farmer surfaces. Auth state is managed client-side via cookies set by the `/api/auth/*` handlers, and the farmer layout gates access to protected routes while the marketing layout provides locale-aware navigation. A single `globals.css` and `global-not-found.tsx` apply cross-route styling and fallbacks.
