Each directory under `app/api/` maps to an HTTP endpoint via Next.js App Router file conventions (e.g. `auth/login/route.ts` → `POST /api/auth/login`). The module is split into two top-level namespaces: `auth/` for the full credential + verification lifecycle (`login`, `signup`, `logout`, `forgot-password`, `reset/password`, `reset/resend`, `reset/verify`, `signup/resend`, `signup/verify`) and `health/` for a simple DB connectivity probe. Route handlers are thin controllers that delegate all cross-cutting concerns to shared libraries in `@/lib/*`: schema validation via Zod schemas in `@/lib/validation/auth`, rate limiting via `@/lib/auth/rate-limit`, pass/token cookie management via `@/lib/auth/pass`, email/code delivery via `@/lib/auth/code-flow`, i18n error messages via `@/lib/auth/copy`, and Supabase client access via `@/lib/supabase`. Handlers never implement business logic themselves — they parse input, enforce rate limits, call domain helpers, and return standardized JSON responses built with `jsonResponse`/`errorResponse` from `@/lib/http`.
