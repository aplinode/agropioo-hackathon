Components are organized by usage context at the top level of `components/`: marketing page sections (`Hero`, `Features`, `FinalCta`, `Footer`, `Journey`, `PakistanFirst`, `EarlyAccessForm`), chrome/navigation (`Nav`, `SiteHeader`, `Logo`, `language-switcher`), and shared visual primitives (`icons.tsx`, `FurrowMotif`, `suggestion-chip`). Two sub-folders encapsulate application-specific shells: `auth/` provides the split-panel `AuthShell` wrapper plus `stepper`, `member-bounce`, and the reusable `otp-verify` screen that serves both signup verification and password-reset flows; `shell/` provides the farmer-app chrome — `app-sidebar` (desktop rail with route-based active state via `usePathname`), `bottom-tab-bar`, and `page-header`. All components consume a consistent design system through Tailwind utility classes using custom tokens (`agro-forest`, `agro-mint`, `agro-canopy`, etc.) and typography utilities (`display-heading`, `eyebrow`, `rise`, `drift`). Client-side interactivity is gated by the `'use client'` directive on interactive components, while static layout components remain server-rendered. Cross-cutting concerns like i18n (`language-switcher`) and Next.js navigation (`next/link`, `next/image`, `next/navigation`) are imported from the project root rather than re-implemented.
